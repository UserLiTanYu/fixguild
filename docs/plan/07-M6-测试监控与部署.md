# M6：测试监控与部署

> 里程碑：M6 · 状态：未开始 · 预计 1 周  
> 关联设计：[16-测试策略](../design/16-测试策略.md) · [15-配置与环境](../design/15-配置与环境.md) · [19-一期验收清单](../design/19-一期验收清单.md)

---

## 1. 目标

把项目从“能跑”推进到“可交付”：

- 集成测试覆盖核心链路；
- 并发与压测有量化结果；
- 有基础监控与告警入口；
- 一条命令启动全套环境；
- CI 能跑单元测试和集成测试；
- 一期验收清单可逐项勾选。

---

## 2. 前置条件

- M2–M5 功能完成；
- 核心接口、数据库 schema、配置已稳定；
- Docker Compose 可启动 MySQL、Redis、MinIO、RocketMQ、XXL-Job。

---

## 3. 范围

### 做

- Testcontainers（MySQL + Redis）；
- 核心链路集成测试补齐；
- 并发测试与压测；
- Prometheus/Grafana/Actuator；
- Dockerfile 与完整 Compose；
- CI 流水线；
- 一期验收与 tag `m6`。

### 不做

- Kubernetes 部署；
- 多环境蓝绿/灰度发布；
- 全链路 APM（可用 traceId + 日志替代）；
- 生产级告警平台。

---

## 4. 任务清单

### 4.1 集成测试

- [ ] 引入 Testcontainers：MySQL 8、Redis 7
- [ ] 测试基类统一管理容器生命周期
- [ ] 核心链路：
  - 登录 → 创建工单 → 派单 → 接单 → 开始 → 完工 → 确认
  - 拒单 → 重新派单
  - 取消、返工
- [ ] 权限：
  - 无权限 403
  - 平台跨租户查询
- [ ] 租户隔离：
  - A 租户不能通过 uid 查/改 B 租户数据
- [ ] 幂等：
  - 同一 `requestId` 重复创建只产生一条
  - 重复 MQ 消息只处理一次
- [ ] 文件/导出：
  - 导出任务状态流转
  - 文件访问权限

### 4.2 并发与压测

- [ ] 并发接单：100 线程只有 1 个成功
- [ ] 并发创建：工单号不重复
- [ ] 重复请求：10 次只产生 1 条工单
- [ ] 压测数据：10 万工单
- [ ] 指标：
  - 工单分页 p95 < 300ms
  - 创建工单 p95 < 200ms
  - 接单 p95 < 200ms
- [ ] 观察 CPU、内存、GC、慢 SQL
- [ ] 记录压测报告到 `docs/plan/` 或 `docs/` 下

### 4.3 监控

- [ ] Actuator 暴露 `health/info/prometheus`
- [ ] 引入 Micrometer Prometheus registry
- [ ] Prometheus 抓取配置
- [ ] Grafana 面板：
  - JVM 内存/GC
  - HTTP QPS/延迟/错误率
  - 数据库连接池
  - Redis 连接
- [ ] 关键业务指标：
  - 工单创建数
  - 派单数
  - 接单数
  - MQ 消费失败数
  - 导出任务失败数
- [ ] 日志保留 traceId，能从 HTTP 串到 MQ/Job

### 4.4 容器化与部署

- [ ] `Dockerfile`：多阶段构建，运行镜像使用 JRE 21
- [ ] `docker-compose.yml` 增加应用服务：
  - 依赖 MySQL、Redis、MinIO、RocketMQ、XXL-Job
  - 环境变量注入
  - healthcheck
- [ ] `application-prod.yml` 只保留环境变量占位
- [ ] 生产关闭 Swagger、H2 控制台
- [ ] 数据卷与备份说明
- [ ] 一条命令启动：`docker compose up -d`
- [ ] 初始化脚本可从零建库

### 4.5 CI

- [ ] GitHub Actions 或本地等价流水线：
  - JDK 21
  - `./mvnw test`
  - 集成测试
  - 构建镜像（可选）
- [ ] 缓存 Maven 依赖
- [ ] 测试报告归档
- [ ] 失败时输出关键日志

- [ ] 更新 [00-开发计划总览](00-开发计划总览.md) 状态

## 5. 验收标准

- [ ] `mvn test` 与集成测试全部通过
- [ ] Testcontainers 可在 CI 中运行
- [ ] 并发测试结果符合预期
- [ ] 压测指标达到目标或有明确分析
- [ ] Prometheus 能抓取指标，Grafana 有基础面板
- [ ] `docker compose up -d` 一条命令启动全套
- [ ] 生产配置无明文密钥
- [ ] 一期验收清单全部完成或有明确豁免

---

## 6. 风险与注意事项

- Testcontainers 在 Windows/Docker Desktop 上启动较慢，测试分组执行。
- 不要为了测试通过而放宽租户条件。
- 压测数据要单独库/环境，避免污染开发数据。
- 监控指标不要包含用户隐私。
- Docker 镜像不要以 root 运行。
- CI 中 MQ 容器较重，可只跑消费者单元测试，集成测试按需启用。
- 验收清单中的每一项都要有对应测试或手工验证记录。
