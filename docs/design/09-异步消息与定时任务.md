# 10. 异步消息与定时任务

> 所属：[总体设计](00-总体设计.md) · 原文章节：§10

## 10.1 事件清单

| 事件 | 触发时机 | 消费方 |
|---|---|---|
| `WORK_ORDER_CREATED` | 创建工单后 | 通知、统计 |
| `WORK_ORDER_ASSIGNED` | 派单后 | 通知技师、统计 |
| `WORK_ORDER_ACCEPTED` | 接单后 | 通知调度员 |
| `WORK_ORDER_REJECTED` | 拒单后 | 通知调度员 |
| `WORK_ORDER_STARTED` | 开始处理后 | 统计 |
| `WORK_ORDER_COMPLETED` | 完工后 | 通知客户/调度员、统计 |
| `WORK_ORDER_CONFIRMED` | 确认后 | 统计、评价邀请 |
| `WORK_ORDER_CANCELED` | 取消后 | 通知相关人 |
| `WORK_ORDER_TIMEOUT` | SLA 超时 | 通知、升级 |

## 10.4 生产与消费

生产端：

```java
public void publish(WorkOrderEvent event) {
    if (TransactionSynchronizationManager.isSynchronizationActive()) {
        TransactionSynchronizationManager.registerSynchronization(
                new TransactionSynchronization() {
                    @Override
                    public void afterCommit() {
                        send(event);
                    }
                });
    } else {
        send(event);
    }
}
```

消费端基类：

```java
public abstract class AbstractRocketMQConsumer<T> implements RocketMQListener<MessageExt> {

    protected abstract void handleMessage(T message);

    protected int maxRetryTimes() {
        return 3;
    }

    protected abstract String idempotentKey(T message);
}
```

## 10.5 重试与失败表

- RocketMQ 自带重试，默认 3 次；
- 超过重试次数，写 `msg_fail`，状态 `DEAD`；
- 平台端提供“失败消息重试”按钮；
- 重试任务每 10 分钟扫一次 `msg_fail`，按 `next_retry_time` 重发；
- 所有失败消息保留原始 `topic/tag/msgId/body/traceId`。

## 10.6 消费幂等

`mq_consume_log` 唯一键 `(topic, consumer_group, msg_id)`：

1. 插入 `PROCESSING`；
2. 插入成功 → 处理业务；
3. 唯一键冲突 → 查询已有记录：
   - `SUCCESS`：直接 ACK；
   - `PROCESSING/FAILED`：按重试策略继续处理；
4. 业务成功 → 更新 `SUCCESS`；
5. 业务失败 → 更新 `FAILED`，抛异常触发 MQ 重试。

## 10.7 定时任务

| 任务 | 频率 | 说明 |
|---|---|---|
| `workOrderSlaJob` | 每 5 分钟 | 扫描超时工单，发提醒 |
| `workOrderAutoConfirmJob` | 每小时 | `COMPLETED` 超过 7 天自动 `CONFIRMED` |
| `workOrderDailyStatJob` | 每天 01:00 | 生成每日统计 |
| `exportTaskRecoveryJob` | 每 10 分钟 | 恢复卡住的导出任务 |
| `mqFailRetryJob` | 每 10 分钟 | 重试死信 |

要求：

- 每个任务加分布式锁，避免多实例重复执行；
- 任务处理按 `id` 分批，每批 200 条；
- 任务必须幂等：重复执行结果一致；
- 任务日志带 `jobId/traceId/处理数量`。
