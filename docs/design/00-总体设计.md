## 1. 文档说明

### 1.1 这套文档解决什么问题

它不是需求文档，而是**落地设计**：

- 告诉你一期做哪些、不做哪些；
- 给出模块划分、表结构、接口清单、状态机、时序图；
- 给出多租户、权限、MQ、定时任务、并发、缓存、导出、加密的具体方案；
- 给出 6-8 周的迭代计划和验收标准。

文档已按主题拆分为 1 篇总览 + 19 篇专题分册，从下方的“分册导航”进入。开发任务与进度见 [开发计划总览](../plan/00-开发计划总览.md)。

### 1.3 关键设计决策

1. **模块化单体**，不上微服务。先学清楚模块边界，再谈拆分。
2. **所有业务表带 `tenant_id`**，平台数据统一用 `tenant_id = '0'`。
3. **API 对外用 `uid` / `orderNo`**，不暴露自增主键，避免枚举。
4. **工单状态用字符串枚举 + 显式状态机**，不引入工作流引擎。
5. **同步核心链路，异步副作用走 MQ**；MQ 发送失败落 `msg_fail` 表补偿。
6. **并发控制三件套**：分布式锁 + 乐观锁 + 请求幂等。
7. **权限 = Sa-Token + RBAC + 数据范围**；权限缓存用版本号，避免 `SCAN`。
8. **敏感数据 = SM4 加密 + 哈希索引 + 脱敏输出 + 查看审计**。
9. **traceId 贯穿 HTTP / MQ / Job**，所有日志可串起来。
10. **一期不做**结算、发票、银行对接、工作流引擎、复杂风控规则。
