# 11. 并发、幂等、事务

> 所属：[总体设计](00-总体设计.md) · 原文章节：§11

## 11.1 分布式锁

注解：

```java
@DistributedLock(
        key = "'lock:workorder:' + #tenantId + ':' + #orderUid",
        waitTime = 3,
        leaseTime = 10,
        errorMsg = "工单正在处理中，请稍后重试"
)
```

锁的粒度：

| 场景 | key |
|---|---|
| 派单 | `lock:workorder:assign:{tenant}:{orderUid}` |
| 接单 | `lock:workorder:accept:{tenant}:{orderUid}` |
| 完工 | `lock:workorder:complete:{tenant}:{orderUid}` |
| 序列号 | `lock:seq:workorder:{tenant}:{date}` |

注意：

- 锁要包住事务，释放锁在事务提交之后；
- 推荐“门面服务加锁 + 事务服务执行”的两层结构，避免 `@Transactional` 和锁切面顺序踩坑；
- 租约时间要大于事务耗时，或者用看门狗（`leaseTime = -1`）。

## 11.2 乐观锁

`work_order.version`：

```sql
UPDATE work_order
SET status = #{target}, version = version + 1, update_time = NOW()
WHERE id = #{id}
  AND tenant_id = #{tenantId}
  AND version = #{version}
  AND status = #{fromStatus}
  AND is_delete = 0;
```

影响行数为 0 → 抛 `409 并发修改，请刷新重试`。

## 11.3 请求幂等

- 写接口要求 `X-Request-Id`；
- `work_order_command` 唯一键 `(tenant_id, request_id)`；
- 重复请求返回第一次的结果；
- 处理中重复请求返回 `409 请求处理中`；
- 前端生成 `requestId`，重试时复用同一个。

## 11.4 事务与事件

- 核心写操作在一个事务内：工单 + 日志 + 派工记录 + 幂等记录；
- MQ 事件在事务提交后发送；
- 发送失败写 `msg_fail`，由定时任务补偿；
- 不在事务内调用第三方（短信、OSS、OCR），避免长事务；
- 第三方调用放到事务提交后或异步消费者里。
