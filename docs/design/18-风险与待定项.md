# 风险与待定项

> 所属：[总体设计](00-总体设计.md) · 原文章节：§20

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Spring Boot 4 兼容性 | 某些库不支持 | 卡住就降 3.5.x，架构不变 |
| RocketMQ/XXL-Job 本地环境重 | 启动成本高 | 先 Docker Compose；实在不行先用 Spring Event + `@Scheduled`，后续替换 |
| 范围蔓延 | 做不完 | 一期严格按[目标与范围](01-目标与范围.md)中的范围，结算/发票/客户 H5 全部二期 |
| 多租户串数据 | 严重 | 写隔离测试；所有按 uid 查询都校验 tenant |
| 并发/幂等漏洞 | 重复派单/重复完工 | 锁 + 乐观锁 + 幂等表 + 并发测试 |
| 密钥泄露 | 安全 | 环境变量 + `.gitignore`，不复制原项目配置 |
| 时间不够 | 半途而废 | 每周一个可运行里程碑，先闭环再优化 |

## 待定项

- 是否引入 Spring StateMachine？（建议不引入，手写状态机）
- 是否引入 MapStruct？（按需，DTO/VO 多了以后再引入）
- 是否引入 Spring Cache 抽象？（建议直接 Caffeine + RedisTemplate，避免抽象层干扰）
- 是否做客户 H5？（二期，看时间）
- 是否做自动派单？（二期，先手动）
