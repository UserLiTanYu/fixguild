# M7：二期扩展

> 里程碑：M7 · 状态：可选 · 预计 1–2 周  
> 关联设计：[01-目标与范围](../design/01-目标与范围.md) · [05-数据库设计](../design/05-数据库设计.md)

---

## 1. 目标

一期验收通过后，按兴趣选择二期方向。M7 不影响一期交付，所有内容都是可选项。

---

## 2. 进入条件

- M6 完成，一期验收清单全部通过；
- 核心链路稳定，测试与监控可用；
- 有明确的二期优先级和时间预算。

---

## 3. 候选方向

### 3.1 报表与统计

- [ ] 工单日报/月报
- [ ] 技师工作量、及时率、返工率
- [ ] 客户维保频次
- [ ] 平台全局统计
- [ ] 报表导出复用 M5 异步导出

### 3.2 客户 H5

- [ ] 客户报修
- [ ] 进度查询
- [ ] 完工确认
- [ ] 服务评价
- [ ] 客户登录与数据范围（`data_scope = 4`）

### 3.3 结算与发票

- [ ] 服务项目与报价
- [ ] 工单结算单
- [ ] 发票申请与状态
- [ ] 对账单
- [ ] 金额计算单元测试

### 3.4 自动派单

- [ ] 技师技能标签匹配
- [ ] 地理位置与距离
- [ ] 当前工单负载
- [ ] 评分与优先级
- [ ] 派单策略可配置
- [ ] 自动派单失败回落到手动派单

### 3.5 工作流与规则

- [ ] 评估是否引入工作流引擎
- [ ] 评估复杂 SLA 规则
- [ ] 评估多级审批

---

## 4. 约束

- 二期功能不得破坏一期表结构和接口兼容性；
- 新功能必须有独立开关或权限；
- 结算、发票涉及金额，必须补单元测试和审计；
- 客户 H5 必须复用现有租户隔离和敏感数据能力；
- 自动派单必须保留手动派单兜底。

---

## 5. 优先级建议

1. 报表与统计（复用现有数据，成本低）
2. 客户 H5（补齐业务闭环）
3. 自动派单（技术点多，但依赖技师档案质量）
4. 结算与发票（领域复杂，最后做）

---

## 6. 验收

- [ ] 每个方向单独建计划文档或在本文拆分
- [ ] 不影响一期验收
- [ ] 有独立测试与权限控制
- [ ] 文档、API 示例、数据库 schema 同步
